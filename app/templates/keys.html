Create your encryption key

Creating a new key replaces your current one. Your old key stays in this browser so you can still read old mail, but contacts will see a "key changed" warning until they verify your new fingerprint.

The key is generated in your browser and protected by a passphrase. The passphrase is separate from your login password and is never sent to the server.

Export and backup

Keep the backup file somewhere safe. It is useless without your passphrase, but anyone who gets it can try to guess the passphrase offline.

Import a backup

Optional: store the encrypted backup on the server

Off by default. If you turn it on, the server stores your passphrase-encrypted private key. It cannot decrypt it, but anyone with database access could try to guess your passphrase offline, so only do this with a long, random passphrase.

What this does and does not protect

  • Messages are encrypted in your browser. The server stores only ciphertext, but still sees who writes to whom, when, and message sizes.
  • The server delivers the JavaScript that does the encryption. A malicious or compromised server could serve altered code. Published file hashes are at /.well-known/assets.json.
  • A key fetched from the server is not verified until you compare fingerprints with its owner through another channel.
